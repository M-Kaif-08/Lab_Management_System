Base id is uuid PK. stored_files storage_key maximum 255, media_type maximum 100; text_value/comment/reasons maximum 4000; choice_code maximum 40 and unit_snapshot maximum 100. Snapshotted rich text is plain text, escaped by rendering. File size limits are configured by purpose before upload/generation.

## Keys and invariants

- UNIQUE (order_item_id, revision) on result_sets. Partial UNIQUE (order_item_id) WHERE state IN ('draft','submitted') allows only one in-progress revision.
- previous_revision_id is UNIQUE when present; all predecessor/amendment links must stay within the same order_item. Revision 1 has no predecessor; later revisions reference the latest prior revision. Lock the item before allocation. amendment_of_id identifies the latest approved revision when correcting approved work and requires a reason.
- UNIQUE (result_set_id, order_parameter_id) on result_values; UNIQUE (result_set_id, sample_id) on result_samples; UNIQUE (result_set_id) on review_events, since a submitted revision receives exactly one decision.
- UNIQUE (report_id, version); previous_version_id must refer to the latest released version of the same report. Failed attempts can leave gaps; allocate version numbers under a reports row lock.
- UNIQUE (report_version_id, result_set_id) and (report_version_id, position) on report_results. A released version may include at most one revision per order item; enforce this through a transaction check/constraint trigger joining result_sets.
- Submitted/rejected/approved result_sets require submitted_by/at; draft rows require them NULL. Submission is irreversible for that revision. Reject with a reason, then create a new draft copied from the rejected revision.
- Approved/rejected states must agree with their review_event decision. Enforce atomically, including reviewer permission and current eligibility.
- Exactly one of numeric_value/text_value/choice_code is non-null for each stored result. Its type must match the ordered parameter. Required parameters must all have a value at submission; optional omitted values have no row. numeric_value must be finite, fit precision and satisfy the parameter decimal_places; reject excess precision before PostgreSQL coercion. Choice codes must belong to the ordered choices snapshot.
- report_versions released state requires file_id, released_by and released_at; other states require released_by/at NULL. A release requires a ready file of purpose report and correct checksum/content. No API exposes building/failed artifacts as final reports.

## Range selection and specimen evidence

Each result_set links the actual samples used. Samples must belong to its order, be linked to its order_item, have compatible specimen type and be received/processing/completed, never rejected. At least one sample is required for these specimen-based tests. Lock sample rows and recheck on submission/approval. A sample cannot be rejected after a submitted/approved revision uses it without first following the controlled rejection/amendment workflow.

applied_range has keys source_id (UUID or null), reference_sex, age_days (integer or null), age_estimated (boolean), low_value/high_value (decimal strings or null), display_text and basis_time (ISO timestamp). unit_snapshot equals the ordered unit. Numeric flags use inclusive bounds; nonnumeric/no matching range uses not_applicable.

Use the earliest collection event among the linked samples as basis_time. Age is calendar days between snapshotted birth date and collection date in lab timezone. Unknown age only matches age-unbounded ranges; estimated age stays explicitly labeled. Prefer an exact reference_sex match; otherwise use any. Within that category, age intervals may not overlap for active ranges: catalog edits lock the parameter owner test and reject overlaps. If no range matches, retain null bounds and not_applicable; never invent a clinical range. A result comment explains relevant uncertainty according to lab policy.

Store the selected range with the value and freeze it on submission. Clinical range definitions and age policy require pilot-lab validation; the schema does not supply medical reference values.

## Revision and review transactions

Lock order → item → relevant samples → result_set, using UUID order within each group, after the foundation actor authorization locks. Draft values are editable with expected row_version. Submission checks completeness, specimen state, range selection and permissions, then freezes value/sample-link content.

Submitted → approved or rejected requires a reviewer. Enforce self-review policy; baseline default denies the entering user from approving their own set. Review writes state, review_event and audit together. Approved values, submitted values and review events cannot be updated/deleted by runtime. A deferred constraint trigger checks review/state consistency at commit.

Corrections create new revisions. The latest approved revision remains authoritative while an amendment is pending. Approval of a newer amendment makes it authoritative by highest approved revision number; do not change or erase the older approved record. Approve only a revision based on the current latest approved revision and current order/patient correction context.

Order patient identity correction after submission records a patient_changes entry if needed and a dedicated audit with a reason. Existing snapshots/reports remain unchanged. The new report content_snapshot uses explicitly reviewed corrected identity, records the original order snapshot plus the correction reason, and creates an amended report version. Do not bypass result review when result content also changes.

## Report and file publication

One reports row groups versions for an order. content_snapshot is a versioned object with schema_version=1, lab identity/branding/footer, patient identity, order number, timezone, rendered test/parameter values/units/ranges, reviewer names/IDs, included result revision IDs, pending/cancelled test lists, correction reason and template_version. Validate the full JSON contract server-side; database CHECK requires an object. Capture all rendering inputs, never query live catalog values to reproduce an old report.

To publish:
1. Lock order, relevant items and then report; authorize, select current approved revisions and insert building version, report_results and content snapshot in a transaction. Follow the global lock order in the database overview.
2. Render a private PDF to a new immutable storage key; verify bytes, checksum and file metadata. A failed render marks the attempt failed, without a final report.
3. Re-lock the same records, revalidate current approvals/identity and policy, attach a ready file and commit released state with audit. If anything changed, fail the attempt and rebuild.
4. Only released versions are downloadable by authorized users. Retain earlier released bytes even after amendment. A report release with pending tests is visibly partial; forbid it when partial release policy is disabled. Replacing previously reported values or patient identity requires correction_reason and a previous released version link; a later release that only adds newly completed tests is a new version without mislabeling the earlier partial report as incorrect.

File writes are not database transactions. Reconcile orphaned pending/failed objects after a grace period, never delete a referenced ready artifact. Backup the consistent database and every referenced file; verify checksum on restoration.

v0.3 adds lab_settings.logo_file_id uuid? FK stored_files. Migrate any existing logo_file_key by registering/validating its file and linking it; retain the old column until verified, then remove it in a subsequent migration. New writes use logo_file_id. Branding changes do not change prior report snapshots/files.

## Indexes and verification

Add result_sets (order_item_id,state,revision DESC); result_values (order_parameter_id); result_samples (sample_id); review_events (reviewer_id,decided_at); report_versions (report_id,state,version DESC); report_results (result_set_id); stored_files (status,created_at). UNIQUE parent-prefixed indexes already serve normal child joins. Index uncovered actor/predecessor FKs where required by maintenance queries.

Verify wrong-parameter/wrong-order samples, numeric precision, missing required values, ambiguous ranges, self-review, concurrent approval/amendment, attempted frozen-value edits, partial reports, file-generation failure and state changes during rendering. No released document may silently change.
